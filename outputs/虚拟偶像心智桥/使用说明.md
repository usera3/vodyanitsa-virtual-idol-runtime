# 虚拟偶像心智动作桥

本桥把 YuriOS 的已提交对话事件交给 Agnes 做自然语义动作规划，把清理后的台词送入现有 Qwen3-TTS/口型桥。已有 ARDY 动作语义匹配时直接复用；没有匹配项时调用常驻 MiniLM ARDY 生成、转换、保存并播放。YuriOS 和语言模型不直接写逐帧骨骼。

当前数据流：

`YuriOS 事件 → Laya 肌肉记忆 / 星火润色 *描写* → ARDY 动作记忆或新生成 → 语音播放门 → 动作总线 → 沃雅妮莎`

`YuriOS 回复 → Qwen3-TTS → DAC 时钟口型 → 动作总线 voice/mouth → 沃雅妮莎`

`拟人反射（30 Hz）→ 呼吸、头颈微动、眼珠漂移、非周期眨眼 → 动作总线 behavior → 沃雅妮莎`

安全边界：

- 正常路径由 Agnes 理解用户原话并输出 `none / catalog / generate` 结构化决策；角色回复里的舞台描写不会自触发。
- Agnes 只能选择保存库已有 ID，或输出以 `A person` 开头、2–10 秒的 ARDY 英文提示词；越界 ID、低置信度和无动作意图不会执行。
- 旧关键词/正则动作规则已清空；API 异常时不会退回旧动作库。活动动作只能直接或间接来自 ARDY。
- 默认要求目标角色已订阅动作总线；角色离线时只记录 deferred，不会盲播。
- SSE 重连后的重复消息按事件 ID 去重。新用户回合使旧规划结果过期，迟到的 ARDY 结果只保存、不抢占新动作。
- 语音继续由现有 `虚拟偶像语音桥` 负责播放和 A/I/U/E/O 口型。语音桥在音频合成及口型计划完成后、打开声卡前原子写入 `audio_ready`；保存动作会等待这个门，再与声音同时启动。用户开始新一轮说话时，旧语音和动作都会停止，并发送闭嘴帧。
- `embodiment_controller.py` 是不调用大模型的确定性拟人层。它以 30 Hz 持续输出全身待机：错开的呼吸波（腹→脊→胸→肩→头，吸气更慢）、约 6.4 秒换重心、独立扫视、非周期眨眼，以及每隔几秒的短 fidget（转头、环视、换脚、歪头、转肩、活动手腕）。倾听时幅度变小并略前倾；说话时加重点头。全身/上半身 ARDY 动作期间，躯干与头部微动降为 20%，眼神和眨眼继续。手臂保持已验收的约 12° 垂臂，不写髋部平移。改完拟人层后需重启心智动作桥才会进实时窗口。

启动前需要：

1. YuriOS 心智服务运行在 `http://127.0.0.1:8768`。
2. 动作总线运行在 `http://127.0.0.1:39538`。
3. 沃雅妮莎已经用 profile `vodyanitsa` 订阅动作总线。

双击 `启动心智动作桥.cmd`。运行状态原子写入 `运行状态.json`。
改完拟人层或听觉后，用同目录的 `重启心智动作桥.cmd` 让实时窗口加载新代码。

听觉在 Windows 上跑：双击 `启动听觉.cmd`。它用本机已有的 `faster-whisper-base` 听麦克风，把识别出的中文/英文 POST 到 YuriOS `/api/chat`。YuriOS 的 STT 保持 fake，不要再在 WSL 里装识别。开口时身体进入 listen，规划时 think，她说话时 speak。
每次连接、动作、语音、打断与错误同时追加到 `审计记录.jsonl`，便于回放问题而不依赖最后一条状态。

## ARDY 动作记忆

旧的 CMU、Kimodo 和旧示例动作已经全部退出活动库。活动目录只允许直接或间接来自 ARDY 的动作：

- 元数据：`../Mocap动作总线/clips/generated/library.json`
- 可播放 clip：`../Mocap动作总线/clips/generated/ardy-*.json`
- 原始 NPZ：`C:/Users/mozi/Documents/Codex/2026-09-14/ardy-github-blender/outputs/motions/ardy-*.npz`

动作使用 ARDY prompt + 时长 + 模型版本的 SHA-256 前 20 位作为稳定缓存键。成功生成后保存来源用户表达、调用次数、创建/最后使用时间、模型和 MiniLM 文本编码器信息。后续自然语言相似时 Agnes 会优先选择保存动作，直接调用 `/api/generated-action`，不重复生成。

常驻 ARDY worker 在桥启动时预热。本机验证中，新复合动作生成 100 帧/20 FPS 约 17 秒；换一种中文说法复用同一动作时，完整规划与调度约 4.35 秒，动作本身无需重新生成。

Laya 0.3.20 System One 已作为 GPU 常驻反射层接入，环境位于 `D:/AI/Laya/venv`，搭配本地 `bge-small-zh-v1.5` 从保存库检索候选。门控有两条安全路径：Laya choice 与 BGE 第一名一致、choice confidence ≥ 0.62 且 BGE ≥ 0.75；或者 BGE ≥ 0.80 且领先第二名 ≥ 0.12。两条路径都要求身体动作概率 ≥ 0.08；身体动作概率 ≤ 0.02 时可直接判定无需动作。模糊近邻仍交给 Agnes。

12 条中文校准（4 条熟悉同义、3 条普通聊天、5 条不同新动作）在上述阈值下为 12/12。正式链路中，企鹅动作复用约 207 ms；普通天气聊天约 95 ms 判定无动作；第二条“三圈 + 鞠躬”动作在阈值实测修订后约 94 ms 直接复用。Laya 与 BGE 均运行在 RTX 5090 D v2，ARDY 和 Qwen3-TTS 继续共存。

本轮验证结果见 `验证报告.json`。真实“跳个舞”由 Agnes 选择保存动作；目录外“企鹅步 + 左手挥手 + 站好”由 ARDY 新生成并播放，随后不同中文表述命中同一保存动作并把 `use_count` 从 1 增加到 2。

## Yuri 动作草稿与场景落地

Yuri 回复里只要出现 `*舞台动作描述*`，就会送去讯飞星火 `spark-x2.5-4b` 润色成 `A person ...` 英文提示词，再交给 ARDY 生成或复用，并与 TTS `audio_ready` 一起播。普通聊天同样适用。用户明确说跳跃/跳舞/挥手/鞠躬时仍走本地模板或 Laya 保存库，不再调用 Agnes。

`config.json -> planner.scene` 是 Blender 当前场景事实。现在场景是只有平地、没有交互物体的空舞台，因此窗户、窗台、座椅、桌椅、墙面等词会被删除或改写成角色可独立完成的原地身体动作。生成提示词若仍引用禁用物体会被拒绝并自动要求 Agnes 修复一次。详细舞蹈草稿不得压缩成单一步骤；手指交握、轻轻摇曳、脚尖画弧和看向前方会分别转成手臂、躯干、脚步和头部动作。

2026-09-25 已用 Yuri 的“拘谨、轻柔摇曳、脚尖画弧”描述生成并保存 `ARDY · 柔和脚尖舞`，原来信息过少的通用舞蹈已移出活动库。短命令“跳舞”通过保存的用户原话精确命中，在 Laya 确认它是动作意图后直接复用；实测 Laya 决策 32.7 ms，音频就绪到动作调度 33.2 ms。

## ARDY 首次生成加速

本机慢点来自 ARDY 进程第一次模型前向编译。相同 5 秒、100 帧、完整 10 步舞蹈首次生成实测 16.437 秒；用 0.4 秒、1 步动作预热后，完整 10 步生成降到 1.261 秒。心智桥启动时现在会在后台自动预热，预热文件不会加入动作库。正式生成继续使用完整 10 步和足部接触修正；无需为了速度改用动作幅度更弱的 4/6 步结果。

## 2026-09-26 延迟与根位移修复

“跳跃”失败回合的真实时间线：用户事件到 Laya 为 49.6 ms；旧桥等待动作草稿 12 秒后并发请求第二次 Agnes，35 秒后超时，动作链在第 48 秒结束；Yuri 主回复到第 73 秒才提交；TTS 只用了 0.89 秒。另一轮取消并发动作规划后，Agnes 主回复仍曾抖动到 122 秒，因此主要瓶颈是免费主模型排队，第二个并发 Agnes 请求会进一步恶化它。

常见明确命令现在不再等待 Yuri 或调用第二次 Agnes：`跳跃 / 跳舞 / 挥手 / 打招呼 / 鞠躬 / 微笑` 走本地反射模板，立即用本地 TTS 回一句“好”，并调用预热 ARDY 或表情源。未知动作才在 Yuri 回复提交后使用动作草稿和 Agnes，不再与主聊天并发竞争。

受控“跳跃”总线测试曾测得本地计划 28 ms、确认语音 0.815 秒、Hips 数据跨度 0.498808 m。但把该根位移直接送进带衣裙刚体的 Blender 后造成衣服物理错乱，用户也没有看到可靠跳跃。该实现已在 2026-09-26 回滚，运行版和源码都恢复为冻结骨骼平移的安全版本。以后不得直接恢复这段 Hips 改动；真正的离地需要单独设计物理感知的角色根控制与裙摆重置/连续碰撞方案。

NPZ 转换原来每次启动独立 Python，约占 2.57 秒。现在使用 ARDY Python 的常驻转换器，SciPy 只在桥启动时加载一次，80 帧转换实测 0.097 秒。低幅度的旧“柔和脚尖舞”已归档；其髋部跨度只有 0.173 m、腿部旋转约 15–16°，不再作为成功舞蹈复用。

## Spark-X2.5-4B 云端聊天

2026-09-26 按用户选择，将 Yuri 的 chat 与 utility 模型热切换到讯飞星辰 MaaS 的 `spark-x2.5-4b`。连接 profile 为 `spark-free`，OpenAI 兼容端点为 `https://maas-api.cn-huabei-1.xf-yun.com/v2`。密钥只保存在 WSL YuriOS 的 `runtime/.env`，环境变量名为 `YURIOS_MODEL_API_KEY_SPARK`；项目、动作库、Vault、日志和验证报告都不保存密钥。

当前参数：聊天与 utility 思考均关闭，temperature 0.85，单次回复上限 256 tokens，context gauge 262144。真实 3169-token Yuri 提示词测试从提交到完整回复为 2.832 秒；直接最小 API 测试为 0.921 秒；随后 Qwen3-TTS 合成耗时 1.072 秒。Prompt trace 已确认实际模型为 `lm_studio/spark-x2.5-4b`。

原 Agnes 连接仍保留为 `legacy-default`，回退模型是 `lm_studio/agnes-3.0-flash`。本地 Qwen3.8 27B 的 CPU/RAM 卸载试验已按用户要求停止，8085 未监听，Yuri 没有连接它。

“跳支舞”未执行的另一原因是短语匹配只覆盖了连续的“跳舞”，随后虽由 Agnes 与 ARDY 生成成功，动作总线因生成 clip 不可用返回 400。当前已补充 `跳支舞 / 跳个舞 / 来一段舞 / 跑步` 等本地模板，并让 HTTP 错误记录总线返回正文、转换后强制检查 clip 是否真实存在。因衣服物理刚恢复，本轮没有再自动向可见角色试播这些动作。

随后确认 clip 丢失来自常驻转换器的管道编码：Windows 子进程未强制 UTF-8，包含 `Mocap动作总线` 的路径被解码错误，但子进程仍返回 done。`convert_ardy_clip.py` 现已把 stdin/stdout/stderr 固定为 UTF-8，并用真实中文输出目录验证：140 帧 clip 正确落盘，转换 0.145 秒。修复后 `跳舞` 在约 0.86 秒被总线接受，`跑步` 也成功生成并播放；两者均使用已回滚的安全总线，不包含 Hips 根位移。

## 语音表演时间轴

Yuri 回复中的普通台词仍交给 Qwen3-TTS 和口型桥；`*动作描写*` 会按它在回复中的位置转成安全表演提示，并在音频真正开始播放时启动。当前支持：转身/侧身、望向用户/偏头、低头、抬头、点头、微笑、惊讶、深呼吸、放松，以及用低头和轻微侧身近似手指绕衣角/袖口等羞涩小动作。

动作只叠加到已有 behavior 通道的头、颈、躯干、眼睛和表情，不移动 Hips，不直接驱动衣裙物理，也不覆盖 ARDY 的全身动作。多个 `*...*` 段落按前面已说台词的字符比例分布到整段音频；末尾动作最晚从音频 70% 处开始，单个提示至少持续 0.45 秒，避免短句中动作一闪而过。手指逐关节和复杂双臂动作暂未接入，现阶段只做安全近似。

真实 Spark 回复测试已把 `转身、望向、低头、微笑` 四个提示随 `audio_ready` 一起送入拟人层；无动作描写的普通回复不会凭空添加动作。验证记录在 `语音表演时间轴实测.json`。

## 当前姿态、动作释放与待机变化

动作总线现在在 `/api/status -> pose_snapshots` 提供角色当前实际输出的 Hips、躯干、头部、双上/前臂和手腕局部四元数。心智桥在解析动作描写和调用动作规划前读取该快照，并把 `facing_user / hands_neutral / active_action / bone_angles_deg` 作为 `current_pose`。如果角色已经面向用户，文本里的“转身望向你”不会再机械增加转身，只保留视线和轻微姿态调整。未知动作交给规划器时也必须从 current_pose 自然衔接并回到中立姿势。

每个 ARDY 动作结束或被打断后，没有实时来源接管的根、手臂、手腕和腿会用动作总线 `release_parts` 在约 0.5–0.6 秒内平滑回到 identity；之后即使 AGI 不在线也保持中立，不再 hold 最后一帧。`POST /api/action {"actor":"vodyanitsa","command":"reset"}` 可强制执行同一恢复。2026-09-26 安装后已对沃雅妮莎执行一次 reset，双上臂、前臂、手腕与 Hips 均实测为 `[1,0,0,0]`。

待机层每隔约 6–15 秒随机选择偏头看、轻点头、低头、轻笑、深呼吸、放松或羞涩侧头，持续 0.8–1.8 秒，并与原有随机眨眼、慢速视线漂移和呼吸叠加。实流验证在 2.53 秒捕捉到 `idle:shy`；这些动作只使用 behavior 的头、颈、躯干、眼睛和表情，不驱动手臂或衣裙。

## 预生成动作词汇与动作组

`build_curated_actions.py` 使用固定种子和完整 10 步 ARDY 离线生成了 32 个可复用短动作，不在构建时向 Blender 播放。分类为：待机 10、对话 10、情绪 3、原地移动 3、运动伸展 2、转向姿态 2、礼仪 1、舞蹈 1。当前 ARDY 动作记忆总数为 38。

每个动作都带有 `entry_pose=neutral_standing`、`exit_pose=neutral_standing`、mask、固定 seed、最大重复次数、冷却、250 ms 淡入、600 ms 中立释放、离线旋转幅度与末帧偏差。13 个动作被提名为待机候选，只有 8 个通过自动幅度检查；其中真正属于 idle 类的 6 个进入自动宏观待机池。其余 5 个异常候选标记 `review_required=true`，不会自动触发。

动作清单在 `../Mocap动作总线/clips/generated/curated_catalog.json`，8 套动作组在 `action_groups.json`：平静待机、羞涩待机、温暖问候、解释、思考、小热身、原地移动、简单舞蹈。动作组统一使用 `neutral_release`，动作之间预留 650 ms，不允许上一动作未恢复就瞬间切到下一姿态。

宏观待机在用户 30 秒无输入、没有语音、没有规划、没有活动动作且角色在线时才运行；之后随机间隔 40–80 秒。只从安全 idle 动作选择，最近三次不重复，用户开始说话会立即停止并进入中立释放。实流已触发“左右换重心”和“轻柔摇曳”；结束后 Hips、双上臂、前臂和手腕均恢复 identity，Blender 约 30 FPS。验证见 `预生成动作库报告.json` 与 `宏观待机动作实测.json`。

## 语音与动作同步、拟人待机

动作不在用户发话或 AI 文本提交时抢跑。已准备好的动作先等待同一用户回合对应的语音 `audio_ready`；语音桥进入播放状态时同时打开动作门。2026-09-25 的真实 YuriOS 对话中，Laya 用 102.5 ms 找到保存的企鹅动作，随后等待 TTS；`audio_ready` 到动作总线确认调度相差 19.877 ms，说话状态到动作调度相差 17.96 ms。

沃雅妮莎 profile revision 8 的部位订阅为：`mouth ← voice`，`torso/head/eyes/expression ← behavior`，其余身体部位仍由 AGI 或当前 ARDY 动作负责。长于八分钟的现场采样中，behavior 已发送 46,041 包，眨眼 119 次，姿态、网格和头发持续变化；Blender 仍为 29.96 FPS。
