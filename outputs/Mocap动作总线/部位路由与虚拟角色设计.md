# 角色动作工作台 · 第一阶段

目标是让角色拥有可持续运行的身体、声音、表达与行为。本轮落地动作分配层；语音、语言模型、自主行为尚未接入。

## 标签动作（第二步）

在左侧唯一的角色选择框选定目标，再进入“标签动作”菜单，选“日常”或“舞蹈”及具体标签。选作用范围（全身、上半身、双臂），点击动作卡的“调用动作”。默认播一次；勾选“循环”可持续回放，按“停止当前动作”立即结束。播完或停止后平滑返回该角色原有的部位订阅。角色未打开时动作仍会计时，页面会明确提示此刻没有可见角色。

界面更新：角色只在左侧选择一次。左侧依次进入标签动作（日常/舞蹈）、部位订阅（全部、躯干与头、手臂与手部、腿部、面部）、来源状态。全部部位 14 项分两页，每页 7 项；动作卡每页最多 6 项。翻页与菜单切换保持未保存的部位草稿，切换角色会阻止丢失草稿。功能与控制接口不变。

初始四条素材来自用户这台机器已有的动作；另新增 12 条公开 CMU 动捕，编号、标签与使用说明见 [在线动作来源与标签.md](在线动作来源与标签.md)。两类现各 8 条，分页后每页最多显示 6 条。

| 分类 | 动作卡 | 标签 | 时长 |
|---|---|---|---|
| 日常 | 走路挥手 · ARDY | 日常、走路、挥手 | 5 秒 |
| 日常 | 走路挥手 · Kimodo | 日常、走路、挥手 | 4 秒 |
| 舞蹈 | 双臂舞步 A | 舞蹈、双臂、侧步 | 5 秒 |
| 舞蹈 | 双臂舞步 B | 舞蹈、双臂、侧步 | 5 秒 |

舞步 A/B 来自两份不同的 ARDY 生成结果；A 对应 `dance.npz`，B 对应 `ardy_20260914_204147_1fd90a.npz`。A 与另一个同名提示输出文件按 SHA256 确认是完全相同的素材，没有重复展示。走路与挥手在现有素材中同时发生，所以这两个标签指向同一条复合动作，并未虚构独立挥手片段。播放标签动作是角色级别的临时控制，不占用 ARDY/Kimodo 全局输入端口，也不修改 `routing.json`。

`clips/action_catalog.json` 保存标签、分类和 clip ID；`clips/manifest.json` 保存源文件 SHA256、帧率和时长；相邻 JSON 是转换后可调用的姿态。动作调用接口为 `POST /api/action`，请求 `{actor,id,mask,loop}`，停止请求 `{actor,command:"stop"}`。`GET /api/status` 返回 `action_catalog`、`active_actions`、`action_masks`。如需加素材，先确认源文件真有对应动作，再导出标准姿态并登记标签，不要只改文案。

原地根姿态仍不产生角色空间位移；舞步目前可见身体与腿部旋转，但无法保证足底不滑或裙腿不穿模。视觉自然度需在角色 Blender 窗口恢复后验收。真实 AGI + 两角色模拟接收器的短测试见 `标签动作实流验证.json`：一角色上半身舞步输出 66 帧、54 骨骼和 18 表情通道，另一角色保持原始 Mocap 数据，停止后状态恢复；这不是角色渲染帧率或视觉证明。

## 现在怎么用

打开 http://127.0.0.1:39538/，左侧选薇斯纳或沃雅妮莎。角色没有打开时也能预先配置。

1. 设置默认来源，通常保留 AGI Mocap。
2. 在需要覆盖的部位选择另一来源，例如头部用 ARDY、左臂用 Kimodo。
3. 可选择来源的另一侧部位，例如左手腕取右手腕；“镜像”再反射旋转。直接取另一侧与镜像是两个独立操作。
4. 来源断开或缺少某通道时，可回退 Mocap、保持最后姿态或归零。右侧显示实际来源和回退状态。
5. 点击“应用并保存”。默认切换过渡 250 ms，默认通道超时 1 秒，可调整。

“精细控制”支持单骨骼覆盖。优先级为 **单骨骼 > 部位 > 默认来源**。可选择另一角色的逻辑动作输出；例如薇斯纳左臂跟随沃雅妮莎右臂。循环订阅会被拒绝。

角色的逻辑输出可以独立于 Blender 模型运行；离线角色仍可作为已配置动作的组合节点。订阅的内容是经过路由的标准姿态，不含对方蒙皮、刚体和衣物结果。

取消“接收动作”并保存会停止该角色的数据发送，保留最后姿态。角色自身的头发、裙摆物理继续运行。恢复默认按钮先把默认设置填入表单，仍需点“应用并保存”。轮询不会覆盖未保存的输入；多窗口冲突会要求重新载入。

## 来源与能力

| 来源 | 输入 | 本轮能力 | 状态说明 |
|---|---|---|---|
| AGI Mocap | 本机 UDP 39539 | 当前实流 54 骨骼、18 表情通道 | 实时动捕 |
| Kimodo | 本机 UDP 39541 | 标准躯干、头、手臂、手腕、腿，共 20 骨骼 | 外部 VMC 输入或明确标注的已生成动作回放 |
| ARDY | 本机 UDP 39542 | 同上，已适配 Core-27 命名与坐标 | 外部 VMC 输入或明确标注的已生成动作回放 |
| 角色逻辑输出 | 总线内部 | 该角色已组合的姿态及表情 | 可被另一角色继续订阅 |

Kimodo/ARDY 适配器当前没有输出手指、眼睛或嘴型；选择这些来源控制对应部位时会使用配置的回退策略。不能把“源在线”理解为它拥有所有通道。

“播放示例”只循环播放本机已生成的走路挥手动作。它不会启动模型推理，也不代表模型正在连续生成。关闭总线后不会自动恢复回放。AGI 实时内容仅在内存保留最新状态，不录制历史动作。

当前根姿态路由控制骨盆旋转，模型保持原地活动；空间行走、足底接触/IK、避障、翅膀等非人体附属骨骼尚未纳入。跨部位组合的视觉自然度仍需要逐角色检查，数学正确不能代替动画验收。

## Kimodo / ARDY 实时发布入口

源程序需要先在其自己的 Blender 中正常运行。当前提供 `source/blender_publisher.py`，在该 Blender 的 Python Console 显式执行：

```python
import sys
sys.path.insert(0, r'C:\Users\mozi\Documents\Codex\2026-09-22\codex-threads-01a0c798-e451-7d22-bd56-4\outputs\Mocap动作总线\source')
import blender_publisher
blender_publisher.start('ardy')  # Kimodo 改为 'kimodo'
# blender_publisher.stop()     # 停止发布
```

ARDY 读取 `ARDY_Source/A27_00…`，Kimodo 读取 `Kimodo_Source`。Kimodo 原启动器会禁用源骨架求值；发布器临时启用其依赖求值，停止时恢复原值。ARDY 源隐藏后停止发布，避免把结束后的旧姿态持续报为新动作。

外部 VMC 输入可能来自生成器或 Blender 时间轴，面板不会仅凭 UDP 活跃便宣称“实时生成”。适配器的骨架采样用于本轮真实素材导出，已验证转换成功；运行中的连续生成器到 Blender 角色的完整视觉链路尚未验证。

## 为什么先做这层

未来每个角色有独立的状态和控制分配。推荐分开承载以下信息：

| 信息 | 例子 | 处理方式 |
|---|---|---|
| 连续姿态 | 身体、手、视线、面部权重 | 保留最新值、时间戳、有效期，丢掉过时帧 |
| 有时间轴的媒体 | 语音音频、嘴型、字幕 | 用 utterance_id 与同一播放时钟对齐 |
| 事件和命令 | 打招呼、打断说话、切换动作 | 使用命令 ID、确认结果、取消机制 |
| 持续角色状态 | 心情、注意目标、当前任务 | 按角色保存，显式版本变更 |

下一阶段先接语音与嘴型，让一段话能可靠开始、同步和中断；之后接文本对话与行为规划，再增加自主视线、呼吸、微动作和场景移动。语言模型输出“看向用户并解释”的意图，行为控制层将其拆成视线、表情、动作与语音；最终由同一个角色控制分配器解决冲突。

后续可增加“紧急停止 > 用户接管 > 明确动作任务 > 对话手势 > 日常微动作”的优先级和可撤销的控制租约。这些属于后续设计，本轮没有假装实现完整调度器或自主智能体。

## 已验证与实际边界

- `source/test_hub.py`、`source/test_router.py`：13 项测试通过，包含原始流双订阅、自动重连、父级局部旋转组合、镜像、覆盖优先级、超时/保持/归零、角色间循环拒绝、面部分组和配置冲突。
- 浏览器验证：部位配置保存、左右镜像、单骨骼从另一侧取动作、回放状态和无页面错误。
- `部位路由实流验证.json`：打包版接收真实 AGI，同时组合 ARDY 头部、Kimodo 左臂，收到完整 54 骨骼与 18 表情通道，约 3.03 秒收到 92 个混合数据包，解析错误为 0。此为传输与姿态通道验证，**不是 Blender 的渲染帧率或最终视觉验收**。
- 角色物理参数未修改。薇斯纳在升级前已自动保存完整场景备份。此轮重新启动其 Blender 被执行策略阻止，需通过已有角色启动入口重新打开后再做视觉确认。

## 开发接续

配置：`运行状态/routing.json`，原子替换写入；角色 ID 为 `vesna`、`vodyanitsa`。不要用易变的进程 UUID 保存用户路由。

控制 API 保持 `service=mocap-pubsub, protocol=1` 兼容旧订阅器，新增 `routing_version=2`。旧订阅请求的 `topics=["agi/main"]` 是兼容握手；实际角色输出由 `profile_id` 和配置决定，不能再把它解释为强制全身 Mocap。

- `GET /api/status`：来源、能力、角色配置、实际通道来源、订阅实例。
- `POST /api/profile`：`{id, expected_revision, profile}`。支持新增配置，最多 32 个；已有配置必须匹配 revision。
- `POST /api/playback`：`{source, clip}` 开始本地示例；`{source, action:"stop"}` 停止。
- 原订阅和退订 API 保留。也可在订阅体显式传 `profile_id`；旧启动器按精确角色名称匹配。

核心旋转先从源世界旋转还原到父级局部，再组合回一致的世界旋转；保留 AGI 的骨长参考。当前手指、眼球沿用安装版 VMC 接收器的独立旋转约定。不同骨架适配器先输出统一契约，不能只截取几条世界旋转直接粘在另一个身体上。

AGI 的表情实包是 `/VMC/Ext/Blend/Val ,if`，编号对应本机元数据中的 VRM.BlendShapePreset 0…17。缓存将其规范为名字；默认原始转发仍字节不变，Blender 订阅器在进程内把编号转换为规范名字再交给 VMC Link。不要把数字编号当作非法包，也不要按模型 shape-key 序号解释。

本轮采用本机 UDP + HTTP 控制的轻量实现，借鉴主题、订阅、有效期和控制权思想，没有安装 ROS 2、MQTT 或蓝牙栈。语音等媒体未来应使用独立流与同步契约，不往骨骼数据包里塞音频。
